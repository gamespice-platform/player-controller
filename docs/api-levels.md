# API levels

Moved from `gs_player_controller_api.gd`; one line per level, newest last. The rule for bumping is on GameSpice Core's `GSAddonApi`.

- 1: everything before this file existed.
- 2: GSPlayerViewRules (mp_forceview) and GSPlayerBodyRules (mp_solidplayers: mask(), apply_to(), apply_hull()); GSFpsBody.pass_out_mask, GSFpsController.set_pass_out_layers; GSTpsCameraRig's arm is a GameSpice Core GSCameraBoom (same spring_length, margin, collision_mask, add_excluded_object), fade_mask/set_fade_mask() and its fade.
- 3: GSFpsSimulator (a second motor over a copy of a player's body: step, command, oracle, mechanics, EVENT_*), GSFpsController.simulator(), GSFpsBody.copy_for_simulation() and copy_filters_to() (flat and physics bodies copy themselves).
- 4: GSFpsViewMotion.body_roll()/body_yaw() and wall_run_body_roll/_yaw/_response (the pose of a drawn body on a wall), exported on GSFpsView.
- 5: GSFpsSampler latches button presses between samples (handle_event takes every event, sample() also polls is_action_just_pressed once a frame), so a mouse-wheel tick on jump is one press of jump in a command.
- 6: GSFpsLadderMode (volumes, climb_speed, jump_off_speed, reach, update()).
- 7: GSFpsSwimMode.friction/set_cvar/cvar_specs (sv_wateraccelerate, sv_waterfriction) and GSFpsLadderMode.dampen/set_cvar/cvar_specs (sv_ladder_dampen).
- 8: GSFpsCvars (fp/core): binds the cvar_specs of tunables, swim and ladder to a console, and map_config_keys() for GSGameMapConfig.
- 9: GSPlayerBodyRules.pair_fn/blocks()/refresh()/apply_exceptions() and GSFpsController.set_extra_excludes(): per-pair pass-through (GameSpice Team's mp_teamblock).
- 10: GSFpsNetSync.rewind_specs()/pack_timers()/unpack_timers(): the jump timers in net_timers.
- 11: GSFpsSprintRules (sprint and stamina cvars as one live group), GSFpsTunables.sprint_toggle (sv_sprint_toggle, applied by GSFpsSampler), and `sprinting`/`sprint_blocks_aim` in motion().
- 12: GSPlayerController.apply_external_velocity(dv): a push (tornado, explosion) the controller keeps.
- 13: GSPlayerViewRules.first_person_body (BODY_OFF, BODY_LEGS, BODY_FULL), own_body(choice) and the `mp_fp_body` cvar (off, legs and feet, whole body; default legs). `mp_fp_legs` is still accepted by set_cvar but no longer registered; `first_person_legs` reads the new value.
- 14: `GSFpsMotor.idle_fast_path`, `idle_full_every` and `idle_ticks`: a cheap tick for a settled, idle, grounded body that wakes on any change (docs/collision.md).
- 15: `GSFpsPhysicsBody.cost_system`: while gs-core's `GSFrameCost` is enabled (gs-core level 30), every script-path query and each native slide, sweep and rest call is charged to it by kind, so gs-profiler's query table shows the controller's collision work.
- 16: `GSFpsMotor.native_tick` and `native_full`: a player tick in one native GameSpice Sim call (halves, or the whole tick with `native_full`), bit-identical to the script; `GSFpsBody.native_tick` is the hook a body answers it through.
- 17: `GSFpsBody.set_hull_world(world, slot)` (hulls from GameSpice Sim's `GSSimHullWorld`, mode 3) and its hull-body and physics-body overrides; a no-op returning false without the library.
- 18: a settled body (`reuse_settled_ground`, native start included) no longer keeps its ground stamp for ever when it stands still: a start check that reused the stamp does not excuse the end check, so a floor removed under it is noticed within two ticks. No new API; a game that needs the fix guards on this level. With `native_full` the fix is in GameSpice Sim's `full.rs`, so the library must be GameSpice Sim v0.2.2 or newer (an older library keeps the stale stamp; the script path is correct at any version, and `motor_native_tick_parity` fails against an older library).
- 19: `GSFpsMotorBatch` (`start`, `add`, `finish`, `skip`, `moved_after`): every player's motor tick of a game tick in one gs-sim call (`GSSimMotorBatch`), bit-identical to ticking them one by one; with it `GSFpsController.begin_tick` and `end_tick` (a tick's start and end around a batched motor step), `has_external_velocity`, and `GSFpsBody.native_batch` and `native_batch_done`, the hooks a body joins a batch through.
- 20: `GSFpsController.phase_timers` (static): fills `phase_us` without `GSFpsMotor.profile`, which also switches the native motor off, so a bench times the controller's phases on the path players really run.
- 21: `GSFpsSlidePreset` (`apply_run`, `apply_sprint`): the two slide setups FC and Zombie Zone each carried, as shared data over `GSFpsTunables.slide_*`.
- 22: `GSFpsLiftCycle.gate_open(seconds, at_top)`: true only while the car stands at that stop, so a game can shut a barrier across a landing's edge whenever the car is elsewhere.
- 23: `GSFpsSlidePreset.cvar_table(prefix)`: the slide's operator cvars (`<prefix>`, `_boost`, `_min_speed`, `_duration`, `_friction`, `_cooldown`) as `cvar -> [member, description]`, so a game names them without copying the table.
- 24: `GSFpsNetSync.rewind_specs2()`/`pack_timers2()`/`unpack_timers2()`: opt-in owner-only `net_timers2` (slide, slide cooldown, wall run in 1/7680 s) so a rewind above 66 Hz restores them exactly; absent, behaviour is unchanged.
- 25: `GSFpsController.previous_position()`: the previous tick's position, equal to `render_state(0.0).position` without copying the state (a server reading it per player per tick).
- 26: `GSFpsMotorBatch.add(..., delta)`: a row's own tick length (a server body that sat out ticks makes them up in one row); without it the row ticks `start`'s delta as before.
- 27: `GSFpsMotor.native_tick` is on by default, so every game's plain ground and air ticks run in GameSpice Sim when the library is there (bit-identical to the script); a game that wants the script sets it false.
- 28: `GSFpsTunables.aim_button`/`aim_speed_scale` (`sv_ads_speed_mult`): ground speed while a move-command aim bit is held, applied in `speed_for` so prediction, the server and the native tick agree.
- 29: `GSFpsController.observe_stats`: off skips folding each tick into `stats` (jumps, strafe sync) for a game with no run HUD; `airborne_time` is kept either way.
- 30: `GSFpsTunables` setters ignore a same-value write: `revision` moves only on a real change, so a game may assign a tunable every tick without dropping `GSFpsMotor`'s cached native settings.
- 31: `GSFpsMotorBatch` lets GameSpice Sim's `run_rows` (when the loaded GameSpice Sim has it) run each row's clocks (timers, cooldowns) with the move, so a row's script prepare skips them; `GSFpsMotor.batch_cancel(state, command, delta)` takes the row's tick to settle those clocks. Answers stay `simulate`'s to the bit.
- 32: `GSFpsController.render_position(alpha)`: `render_state(alpha).position` without copying the state, for a reader that needs only where a body is drawn (a killcam recording every body each frame).
- 33: `GSPlayerHullRewind` (`around`, `rewind`, `restore`, `feet_fn`, `snap_fn`, `reach`): lag-compensated collision for `apply_hull` capsules, and `GSPlayerBodyRules.unlag` / `mp_solidplayers_unlag` (replicated, 0 by default), which `follow_cvars` and `bind_cvars` carry.
- 34: `GSFpsMotorBatch.post_row(row, into, at)` and `POST`: a finished row's state after its motor (velocity x and z, mode, crouch, slide and wall-run times, sprinting), GameSpice Sim's `GSSimPlayerPost` input columns, from the batch's answer where it ended the row.
- 35: `GSPlayerHullView` (`record`, `feet_for`, `around`, `resolve`, `lag_q_for`, `bracket_for`; `snap_fn`, `view_fn`, `client_fn`): the per-tick feet ring, the one view rule both ends share and the client's fill for `GSPlayerHullRewind`, so a game supplies only its position snap, where its command keeps the view fields and the interpolator call.
- 36: `GSFpsStateColumns`: the values of `GSFpsState` the motor tick reads and writes (position, velocity, ground normal, mode, ground id, yaw, previous buttons, the clocks, wall counters and wall normal) live in one packed float64 array per state in that class's layout; the properties are accessors over it. `GSFpsState.columns()` returns the array (one argument GameSpice Sim can read instead of a property read per field). Values and answers are unchanged.
- 37: `GSFpsMotorBatch.native_cols` (on by default) and `cols_runs`: with a GameSpice Sim that has `GSSimMotorBatch.run_cols`, the batch hands it each state's columns and 27 other values a row instead of a 55-value row, and assigns the answered columns back once per player; `GSFpsMotor.batch_prepare`'s `row_len` and `batch_apply_cols` are that path. Answers are unchanged.
- 38: `GSFpsMotorBatch.native_state` (on by default) and `state_runs`: with a GameSpice Sim that has `GSSimMotorBatch.run_states` and `GSSimMotorState`, each motor's rest stamp is kept natively (`GSFpsMotor.batch_motor_state`, `batch_rest_bits`, `batch_states`), the batch decides the start ground reuse and stamps the settled end itself, and the script reads a row's counters only when one counted. Answers are unchanged.
- 39: `GSFpsViewMotion.apply_scales(picks, landing, strafe, wall, widen)`: sets a motion's amounts (landing dip and nod, strafe and slide lean, wall-run lean and eye shift, the three widenings, the roll bound) to a game's picks times the player's four 0..2 scales; a game keeps only its `camera_motion_picks()`.
